Destructuring ES6

💡 Destructuring lets you unpack values from arrays or properties from objects into distinct variables using a concise syntax that mirrors the structure of the data.
✗ Before ES6
const user = { name: "Alice", age: 30, city: "Delhi" }; const name = user.name; const age = user.age; const city = user.city;
✓ ES6 Destructuring
const user = { name: "Alice", age: 30, city: "Delhi" }; const { name, age, city } = user; // name → "Alice", age → 30, city → "Delhi"
// Renaming while destructuring (aliasing) const { name: userName, age: userAge } = user; // userName → "Alice", userAge → 30 // Default values — used when property is undefined const { name, role = "guest", score = 0 } = user; // role → "guest" (missing from object), score → 0 // Rename + default together const { name: n = "Anonymous" } = {}; // n → "Anonymous" // Nested object destructuring const profile = { user: { name: "Bob", address: { city: "Mumbai" } } }; const { user: { name: pName, address: { city: pCity } } } = profile; // pName → "Bob", pCity → "Mumbai" // Rest in object destructuring — collect remaining props const { name: first, ...rest } = { name: "Alice", age: 30, city: "Delhi" }; // first → "Alice", rest → { age: 30, city: "Delhi" }
// Basic array destructuring — position-based const [a, b, c] = [10, 20, 30]; // a → 10, b → 20, c → 30 // Skipping elements with holes const [first, , third] = [1, 2, 3]; // first → 1, third → 3 (2 is skipped) // Default values const [x = 0, y = 0] = [5]; // x → 5, y → 0 (default used) // Rest element — collect remaining items const [head, ...tail] = [1, 2, 3, 4, 5]; // head → 1, tail → [2, 3, 4, 5] // Swapping variables — classic ES6 trick! let p = 1, q = 2; [p, q] = [q, p]; // p → 2, q → 1 (no temp variable needed!) // Destructure function return value function getRange() { return [0, 100]; } const [min, max] = getRange(); // min → 0, max → 100
// Destructuring arrays of objects const users = [ { id: 1, name: "Alice" }, { id: 2, name: "Bob" } ]; const [{ name: first }, { name: second }] = users; // first → "Alice", second → "Bob" // Mixed: object containing array const { scores: [top] } = { scores: [98, 85, 70] }; // top → 98 // Destructuring in for...of loops const entries = [["a", 1], ["b", 2]]; for (const [key, value] of entries) { console.log(key, value); // "a" 1 → "b" 2 } // Object.entries() pattern — very common! const obj = { a: 1, b: 2, c: 3 }; for (const [key, value] of Object.entries(obj)) { console.log(`${key}: ${value}`); } // "a: 1", "b: 2", "c: 3"
✗ Old style
function greet(user) { const name = user.name; const age = user.age; console.log(name, age); }
✓ Destructured params
function greet({ name, age }) { console.log(name, age); } greet({ name: "Alice", age: 30 });
// With defaults in parameters function createUser({ name = "Anonymous", role = "user", active = true } = {}) { return { name, role, active }; } // The = {} at the end lets you call createUser() with no arguments at all createUser(); // → { name: "Anonymous", role: "user", active: true } createUser({ name: "Alice" }); // → { name: "Alice", role: "user", active: true } // Array param destructuring const sum = ([a, b, c = 0]) => a + b + c; sum([1, 2]); // → 3 (c defaults to 0) sum([1, 2, 3]); // → 6

Spread & Rest ... ES6 / ES2018

💡 Same ... syntax, opposite purpose: Spread expands an iterable into individual elements. Rest collects multiple elements into a single array/object. Context tells them apart.
📤 Spread — expand out
Used on the RIGHT side of an assignment or as an argument
// Arrays const a = [1, 2]; const b = [3, 4]; const c = [...a, ...b]; // [1,2,3,4] // Objects (ES2018+) const base = { x: 1, y: 2 }; const ext = { ...base, z: 3 }; // { x:1, y:2, z:3 } // Function call const nums = [5, 2, 8]; Math.max(...nums); // → 8
📥 Rest — collect in
Used on the LEFT side — must be the LAST element
// Function parameters function sum(...nums) { return nums.reduce((a,b) => a+b, 0); } sum(1,2,3,4); // → 10 // Array destructuring rest const [first, ...rest] = [10,20,30]; // rest → [20, 30] // Object destructuring rest const { a, ...others } = { a:1, b:2, c:3 }; // others → { b:2, c:3 }
// ── Practical spread patterns ── // Shallow copy array (avoids mutating original) const original = [1, 2, 3]; const copy = [...original]; // [1, 2, 3] — new array // Shallow copy object const user = { name: "Alice", age: 30 }; const updated = { ...user, age: 31 }; // { name:"Alice", age:31 } — age overwritten // Merge objects — LAST value wins for duplicate keys const defaults = { theme: "dark", lang: "en", size: "md" }; const overrides = { lang: "fr", size: "lg" }; const settings = { ...defaults, ...overrides }; // { theme:"dark", lang:"fr", size:"lg" } // Convert string / Set / NodeList to array [..."hello"] // → ["h","e","l","l","o"] [...new Set([1,1,2])] // → [1, 2] (dedup!) [...document.querySelectorAll("p")] // → real Array with all .map etc. // ⚠️ Spread is SHALLOW — nested objects still share reference const obj = { a: { val: 1 } }; const obj2 = { ...obj }; obj2.a.val = 99; // mutates obj.a.val too!
⚠ Rest must be last: const [a, ...rest, b] = arr → SyntaxError. Rest/spread in object literals requires ES2018+. Spread is always a shallow copy.

Optional Chaining ?. ES2020

💡 Optional chaining short-circuits and returns undefined (instead of throwing a TypeError) when accessing a property on null or undefined. Safe deep-access without verbose null checks.
✗ Before — verbose null guards
const city = user && user.address && user.address.city; const len = arr && arr.length; if (obj && obj.fn) obj.fn();
✓ With optional chaining
const city = user?.address?.city; const len = arr?.length; obj?.fn?.();
// 4 forms of optional chaining // 1. Property access const city = user?.address?.city; // → "Delhi" or undefined // 2. Method call — won't throw if method doesn't exist const upper = str?.toUpperCase(); // → "HELLO" or undefined obj?.fn?.(); // call only if obj AND fn both exist // 3. Bracket notation (dynamic keys) const key = "name"; const val = user?.[key]; // → "Alice" or undefined // 4. Optional function call const callback = null; callback?.("data"); // does nothing — no error // Combine with ?? for a safe fallback const city2 = user?.address?.city ?? "Unknown"; // → city value, or "Unknown" if any part is null/undefined // Real-world: API response drilling const price = response?.data?.products?.[0]?.price ?? 0; // ⚠️ Short-circuit — stops at first null/undefined, returns undefined const u = null; u?.doSomethingWithSideEffect(); // side effect is NEVER called
⚠ Not for assignment: user?.address = "x" → SyntaxError. Optional chaining is read-only. Also: don't overuse it — if something should always exist, a TypeError is a useful bug signal.

Nullish Coalescing ?? ES2020

💡 ?? returns the right-hand side only when the left side is null or undefined — NOT for other falsy values like 0, "", or false. This is the key difference from ||.
Left-hand value?? result|| resultWhy they differ
null → RHS (fallback) → RHS (fallback) Both treat null as missing
undefined → RHS (fallback) → RHS (fallback) Both treat undefined as missing
0 → LHS (keeps 0) → RHS (fallback) ⚠ || treats 0 as missing!
"" → LHS (keeps "") → RHS (fallback) ⚠ || treats "" as missing!
false → LHS (keeps false) → RHS (fallback) ⚠ || treats false as missing!
"hello" → LHS (keeps "hello") → LHS (keeps "hello") Both keep truthy values
// || vs ?? — the key difference const score = 0; score || 100 // → 100 ← WRONG! 0 is a valid score, but || treats it as falsy score ?? 100 // → 0 ← CORRECT! ?? only checks null/undefined // Real-world: form inputs often send "" which is valid const input = ""; input || "default" // → "default" (may not be what you want) input ?? "default" // → "" (preserves empty string) // Chaining ?? for multiple fallbacks const val = a ?? b ?? c ?? "final fallback"; // ??= Assignment operator (ES2021) let config = null; config ??= { theme: "dark" }; // assigns only if null/undefined // config → { theme: "dark" } // Power combo: optional chaining + nullish coalescing const displayName = user?.profile?.displayName ?? user?.name ?? "Guest"; const port = config?.server?.port ?? 3000;
⚠ Cannot mix ?? with || or && without parentheses — a || b ?? c → SyntaxError. Use explicit parentheses: (a || b) ?? c.

Template Literals ` ` ES6

💡 Template literals use backticks (`) instead of quotes. They support embedded expressions via ${...}, true multi-line strings, and the powerful tagged template pattern.
✗ Old string concat
const msg = "Hello, " + name + "! You are " + age + " years old.";
✓ Template literal
const msg = `Hello, ${name}! You are ${age} years old.`;
// Expressions inside ${} — any valid JS expression const a = 5, b = 10; console.log(`Sum: ${a + b}`); // → "Sum: 15" console.log(`Result: ${a > b ? a : b}`); // → "Result: 10" (ternary) console.log(`Upper: ${"hello".toUpperCase()}`); // → "Upper: HELLO" // Nested template literals const items = ["a", "b", "c"]; const html = `<ul>${items.map(i => `<li>${i}</li>`).join("")}</ul>`; // → "<ul><li>a</li><li>b</li><li>c</li></ul>"
// True multi-line — no \n needed const poem = `Roses are red, Violets are blue, JavaScript is great, And so are you.`; // Building HTML templates const card = ({ name, role, avatar }) => ` <div class="card"> <img src="${avatar}" alt="${name}"> <h2>${name}</h2> <p>${role}</p> </div> `; // SQL / multiline queries const query = ` SELECT id, name, email FROM users WHERE active = true ORDER BY name ASC `;
🏷️ Tagged templates let a function process a template literal — receiving the string parts and interpolated values separately. Used in styled-components, GraphQL (gql`...`), SQL sanitization, i18n, and more.
// Tag function signature: (strings, ...values) function tag(strings, ...values) { console.log(strings); // array of string parts console.log(values); // array of interpolated values return strings.raw[0]; // .raw gives unprocessed escape sequences } tag`Hello ${"Alice"}, you are ${30} years old`; // strings → ["Hello ", ", you are ", " years old"] // values → ["Alice", 30] // Practical: HTML escaping (sanitize user input) function safeHtml(strings, ...vals) { return strings.reduce((acc, str, i) => { const val = (vals[i] ?? "").toString() .replace(/&/g, "&amp;") .replace(/</g, "&lt;") .replace(/>/g, "&gt;"); return acc + str + val; }, ""); } const userInput = "<script>alert('xss')</script>"; safeHtml`<p>${userInput}</p>`; // → "<p>&lt;script&gt;...&lt;/script&gt;</p>" // You've used tagged templates if you've used: // styled-components: css`color: red;` // GraphQL: gql`query { user { id } }`
// Conditional rendering pattern const badge = `${isAdmin ? "[ADMIN]" : ""} ${name}`.trim(); // String padding / formatting const pad = (n) => `${n}`.padStart(2, "0"); console.log(`${pad(9)}:${pad(5)}`); // → "09:05" // URL builder const apiUrl = (endpoint, id) => `https://api.example.com/v1/${endpoint}/${id}`; apiUrl("users", 42); // → "https://api.example.com/v1/users/42" // Dynamic class names (React pattern) const className = `btn ${isActive ? "btn-active" : "btn-inactive"} ${size}`; // String.raw — raw template tag, no escape processing String.raw`C:\Users\Alice\node`; // → "C:\Users\Alice\node" (backslashes literal)

Shorthand Properties & Methods ES6

💡 ES6 added several object literal enhancements: property shorthand when key equals variable name, method shorthand (no function keyword), and computed property names with [expr].
Property Shorthand
When variable name matches key name — omit the value.
const name = "Alice"; const age = 30; // Old const user = { name: name, age: age }; // ES6 shorthand ✓ const user = { name, age };
Method Shorthand
No function keyword needed for object methods.
// Old const obj = { greet: function() { return "hi"; } }; // ES6 shorthand ✓ const obj = { greet() { return "hi"; } };
Computed Property Names
Dynamic keys using expressions inside [...].
const key = "name"; const prefix = "get"; const obj = { [key]: "Alice", // → name: "Alice" [`${prefix}Name`]() { // → getName() return this.name; } };
Getter & Setter Shorthand
Define computed/validated properties elegantly.
const person = { _name: "Alice", get name() { return this._name; }, set name(v) { if (typeof v === "string") this._name = v; } }; person.name = "Bob"; // uses setter
Shorthand in Practice
All three combined — extremely common in React & Node.
function createUser(name, age, role) { const id = Math.random(); const createdAt = Date.now(); return { id, // shorthand name, // shorthand age, // shorthand role, // shorthand createdAt, // shorthand greet() { // method shorthand return `Hi, I'm ${this.name}`; } }; }
Dynamic Keys Pattern
Build objects with computed keys — useful for form state & Redux.
// Form field update pattern function updateField(state, field, val) { return { ...state, [field]: val }; } updateField(form, "email", "a@b.com"); // → { ...form, email: "a@b.com" } // Build object from array of keys const keys = ["a", "b", "c"]; const obj = Object.fromEntries( keys.map(k => [k, 0]) ); // → { a:0, b:0, c:0 }

Common Gotchas & Traps

  • ⚠️ Destructuring undefined throws: const { a } = null → TypeError. Always provide a fallback: const { a } = obj ?? {} or check before destructuring.
  • ⚠️ Default values only trigger on undefined, not null: const { x = 5 } = { x: null } → x is null, not 5. Defaults activate only when the value is undefined.
  • ⚠️ Spread is shallow: const c = { ...obj } — nested objects inside obj are still shared references. Mutating c.nested.val also changes obj.nested.val.
  • ⚠️ Rest must be last: const [a, ...rest, b] = arr and function f(...args, last) are both SyntaxErrors. The rest element must always be the final one.
  • ⚠️ Spread merging — last key wins: { a: 1, ...{ a: 2 } } → { a: 2 }. When merging objects with spread, order matters — later spreads overwrite earlier values.
  • ⚠️ Optional chaining on the left side: user?.name = "Bob" → SyntaxError. ?. is read-only — you cannot assign through optional chaining.
  • ⚠️ ?? cannot be chained with || or && directly: a || b ?? c → SyntaxError. Always add parentheses: (a || b) ?? c.
  • ⚠️ Template literal whitespace is literal: Indentation inside a template literal becomes part of the string. Use .trim() or String.raw when exact whitespace matters.
  • ⚠️ Computed property names evaluate once: const key = "x"; const obj = { [key++]: 1, [key++]: 2 } — each [key++] is evaluated at object-literal creation time, left to right.
  • ⚠️ Method shorthand vs arrow function in objects differ in this: greet() {} has its own this (the object). greet: () => {} captures this from the enclosing scope — never use arrow functions as object methods that need this.

Interview Q&A — click to reveal

Q1: What is the difference between spread and rest? They use the same syntax.
+
Same ... syntax, opposite operations. Spread expands an iterable into individual elements — used on the right-hand side of assignments or as function arguments: [...arr], {...obj}, fn(...args).

Rest collects multiple elements into a single array or object — used on the left-hand side of destructuring or as the last function parameter: const [first, ...rest] = arr, function f(...args).
Q2: How would you swap two variables without a temporary variable in ES6?
+
Using array destructuring: [a, b] = [b, a]. The right side creates a new array [b, a], then destructuring assigns the first element back to a and the second to b. No temp variable needed.
let x = 1, y = 2; [x, y] = [y, x]; console.log(x, y); // → 2, 1
Q3: What is the difference between ?? and ||?
+
|| returns the right-hand side if the left side is any falsy value — including 0, "", false.

?? (nullish coalescing) returns the right-hand side only if the left is null or undefined. This is important when 0, empty string, or false are valid values you don't want to override.

Rule of thumb: use ?? for "value not provided" and || for "falsy value — use default".
Q4: What does optional chaining (?.) return when the chain hits null or undefined?
+
It short-circuits and returns undefined — no TypeError is thrown. The rest of the chain is not evaluated. This is useful for safely drilling into deeply nested objects from API responses without wrapping everything in null checks.
const user = null; user?.profile?.avatar // → undefined (no error) user.profile // → TypeError: Cannot read properties of null
Q5: When do destructuring default values apply?
+
Only when the value is undefined — not when it's null, 0, false, or any other falsy value.
const { a = 5 } = { a: undefined }; // → a = 5 (undefined triggers default) const { b = 5 } = { b: null }; // → b = null (null does NOT trigger default!) const { c = 5 } = { c: 0 }; // → c = 0 (0 does NOT trigger default)
Q6: How do you remove a key from an object immutably using ES6?
+
Use object destructuring with rest — destructure out the key you want to remove, collect everything else into a new object:
const user = { name: "Alice", password: "secret", age: 30 }; const { password, ...safeUser } = user; // safeUser → { name: "Alice", age: 30 } (password omitted) // user is unchanged (immutable pattern)
Q7: What are tagged template literals and where are they used?
+
Tagged templates let a function process a template literal — the function receives the string parts as an array and the interpolated values as separate arguments. This enables transformations like HTML escaping, SQL sanitization, i18n, and custom DSLs.

Real-world examples: styled-components uses css`color:red`, Apollo uses gql`query {...}`, and String.raw`C:\path` is a built-in tag that preserves raw backslashes.
Q8: What's the difference between method shorthand and an arrow function as a method?
+
greet() { return this.name } — method shorthand has its own this, bound to the object when called.

greet: () => this.name — arrow function captures this from the surrounding lexical scope (usually the module/global), so this inside the arrow will NOT be the object. This is a common bug.

Rule: always use method shorthand (or regular function) for object methods that need this. Reserve arrow functions for callbacks inside those methods.
Q9: How do you rename a variable while destructuring and give it a default?
+
Combine the rename (:) and default (=) syntax in one expression:
const { name: userName = "Anonymous" } = {}; // userName → "Anonymous" (renamed AND defaulted) const { role: userRole = "guest" } = { role: "admin" }; // userRole → "admin" (value exists, default not used)
The pattern reads: extract the name property, call it userName locally, and if name is undefined use "Anonymous".
