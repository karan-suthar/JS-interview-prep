What is Type Coercion?

💡 Type coercion is JavaScript automatically (implicitly) converting a value from one type to another when an operation requires it — e.g. comparing a string to a number, or adding a boolean to a string.
Implicit (automatic by JS)

Number("5") // → 5 String(42) // → "42" Boolean(0) // → false parseInt("3.9") // → 3 parseFloat("3.9") // → 3.9 +"42" // → 42 (unary + trick)

Truthy & Falsy Values

💡 In a boolean context (if, while, ternary, ||, &&), JS coerces values to true or false. There are exactly 8 falsy values — everything else is truthy.
Falsy Values (only 8!)
false 0 -0 0n "" '' `` null undefined NaN
Note: 0n is BigInt zero; "" '' `` are empty strings (all three quote styles)
Truthy Values (everything else)
"0" "false" [] {} 1 -1 function(){} Infinity new Date()
⚠ "0", "false", [], {} are ALL truthy — common interview trap!
// Falsy in action if (0) console.log("runs"); // ✗ doesn't run if ("") console.log("runs"); // ✗ doesn't run if (null) console.log("runs"); // ✗ doesn't run // Truthy surprises — the common interview traps if ("0") console.log("runs"); // ✓ runs! "0" is truthy (non-empty string) if ([]) console.log("runs"); // ✓ runs! empty array is truthy if ({}) console.log("runs"); // ✓ runs! empty object is truthy if ("false") console.log("runs"); // ✓ runs! non-empty string // || and && use truthy/falsy (short-circuit evaluation) const name = null || "Default"; // → "Default" const val = 0 || 42; // → 42 (0 is falsy) const user = { name: "Alice" }; const n = user && user.name; // → "Alice" (safe property access) // ?? (Nullish Coalescing) — only catches null/undefined, NOT 0 or "" const score = 0 ?? 100; // → 0 (0 is not null/undefined) const score2= 0 || 100; // → 100 (0 is falsy — || treats 0 as missing!)
⚠ Use ?? (nullish coalescing) instead of || when you want to allow legitimate falsy values like 0 or "" as valid defaults. || treats them as missing!

The instanceof operator

💡 instanceof checks whether an object was created from a particular constructor — by walking the object's prototype chain. Returns true or false. Only works with objects (reference types), not primitives.
// instanceof basics [] instanceof Array // → true [] instanceof Object // → true (Array extends Object!) {} instanceof Object // → true function(){} instanceof Function // → true new Date() instanceof Date // → true // instanceof with classes class Animal {} class Dog extends Animal {} const d = new Dog(); d instanceof Dog // → true d instanceof Animal // → true (walks prototype chain) d instanceof Object // → true (everything is an Object) // instanceof FAILS on primitives "hello" instanceof String // → false (primitive, not a String object) 42 instanceof Number // → false (primitive) new String("hello") instanceof String // → true (wrapped object ← but avoid this!)

Interview Q&A — click to reveal

Q1: What is the difference between == and ===?
+
== (loose equality) performs type coercion before comparing — it converts operands to a common type first. === (strict equality) requires both value AND type to be identical, with no conversion.

Always prefer === in production code. The one common exception is val == null to check for both null and undefined at once.
Q2: What are the falsy values in JavaScript?
+
There are exactly 8 falsy values: false, 0, -0, 0n (BigInt zero), "" (empty string — all three quote styles), null, undefined, and NaN.

Common traps: "0", [], and {} are all truthy, even though they may look empty.
Q3: What does "1" + 2 + 3 evaluate to? What about 1 + 2 + "3"?
+
"1" + 2 + 3 → "123". Evaluation is left-to-right: "1" + 2 → "12" (string concat), then "12" + 3 → "123".

1 + 2 + "3" → "33". 1 + 2 → 3 (numeric add), then 3 + "3" → "33" (string concat because "3" is a string).
Q4: Why does 0.1 + 0.2 !== 0.3 in JavaScript?
+
JavaScript uses IEEE-754 double-precision floating-point, which can't represent 0.1 and 0.2 exactly in binary. The result of 0.1 + 0.2 is 0.30000000000000004, not 0.3.

Fix: use Math.abs(a - b) < Number.EPSILON for comparisons, or round using +(result).toFixed(2).
Q5: What is the difference between || and ??
+
|| returns the right-hand side if the left side is any falsy value — including 0, "", false.

?? (nullish coalescing) only triggers the fallback if the left side is null or undefined, not other falsy values.

Use ?? when 0 or "" are valid values you don't want to override with a default.
Q6: What is the difference between typeof and instanceof?
+
typeof returns a string ("number", "string", "object"…) and works on any value including primitives. Best for checking primitive types.

instanceof checks the prototype chain to see if an object was created from a specific constructor. Only works correctly on objects — returns false for all primitives.

Neither is perfect: use Array.isArray() for arrays, === null for null, and Object.prototype.toString.call() for the most reliable type detection.
Q7: Why is NaN === NaN false? How do you properly check for NaN?
+
NaN (Not a Number) is the only value in JavaScript that is not equal to itself — this is intentional per the IEEE-754 standard, because NaN represents an invalid computation and two invalid computations are not necessarily the same.

To check for NaN: use Number.isNaN(value) (preferred — does NOT coerce). Avoid the older isNaN() which first coerces to number (isNaN("hello") returns true even though "hello" is a string, not NaN).
Q8: What does null >= 0 return? (tricky!)
+
true — and this is a notorious JS gotcha. For relational operators (<, >, <=, >=), null is coerced to 0. So null >= 0 becomes 0 >= 0 → true.

But null == 0 is false! The == operator has a special rule: null is only equal to undefined and nothing else. This inconsistency is one of the most-cited JS quirks.
