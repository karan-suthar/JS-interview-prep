.map()

non-mutating → new array

Transforms every element and returns a new array of the same length. Use when you want to change the shape/value of each item but keep a 1-to-1 count.

array.map((element, index, array) => { ... })

⚠ Common mistake: using map when you don't need the returned array (e.g. just to run side effects) — use forEach instead. Also, forgetting to return inside the callback silently produces an array of undefined.

.reduce()

non-mutating → single value

The most powerful/flexible array method — reduces the whole array down to a single value (number, string, object, array — anything) by running an accumulator function over each element.

array.reduce((accumulator, element, index, array) => newAccumulator, initialValue)
// Sum all numbers const nums = [1, 2, 3, 4]; const total = nums.reduce((acc, n) => acc + n, 0); // acc: 0 → 1 → 3 → 6 → 10 // → 10 // Find the max value const max = nums.reduce((acc, n) => n > acc ? n : acc, -Infinity); // → 4 // Count occurrences const fruits = ["apple", "banana", "apple", "apple"]; const count = fruits.reduce((acc, f) => { acc[f] = (acc[f] || 0) + 1; return acc; }, {}); // → { apple: 3, banana: 1 }
// Array of objects → lookup object (keyed by id) const users = [ { id: 1, name: "Alice" }, { id: 2, name: "Bob" } ]; const byId = users.reduce((acc, user) => { acc[user.id] = user; return acc; }, {}); // → { 1: {id:1,name:"Alice"}, 2: {id:2,name:"Bob"} } // Now byId[1].name → "Alice" (O(1) lookup vs O(n) with find) // Flatten a shopping cart into total price const cart = [{ price: 10, qty: 2 }, { price: 5, qty: 3 }]; const totalPrice = cart.reduce((sum, item) => sum + item.price * item.qty, 0); // → 35
// Classic "group by" pattern with reduce const people = [ { name: "Alice", dept: "Eng" }, { name: "Bob", dept: "Sales" }, { name: "Carol", dept: "Eng" } ]; const byDept = people.reduce((acc, p) => { (acc[p.dept] ??= []).push(p); // ??= creates array if missing return acc; }, {}); // → // { // Eng: [{name:"Alice",...}, {name:"Carol",...}], // Sales: [{name:"Bob",...}] // } // Modern alternative: Object.groupBy (ES2024, newer engines) const grouped = Object.groupBy(people, p => p.dept);
🎓 Interviewers love asking you to reimplement map/filter using reduce — it proves you understand reduce is the "parent" of all array iteration.
// Reimplement map using reduce const myMap = (arr, fn) => arr.reduce((acc, el, i) => { acc.push(fn(el, i, arr)); return acc; }, []); // Reimplement filter using reduce const myFilter = (arr, fn) => arr.reduce((acc, el, i) => { if (fn(el, i, arr)) acc.push(el); return acc; }, []); // Chain multiple functions (pipe/compose) using reduce const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x); const process = pipe(x => x + 1, x => x * 2, x => x - 3); process(5); // → ((5+1)*2)-3 = 9
⚠ Always provide an initial value (the second argument). Without it, reduce uses the first array element as the initial accumulator and starts from index 1 — this throws a TypeError on an empty array with no initial value.
F

.find()

non-mutating → element or undefined

Returns the first element that satisfies the test function, or undefined if none match. Stops iterating as soon as a match is found (short-circuits).

array.find((element, index, array) => boolean)
// Find first matching object const users = [ { id: 1, name: "Alice" }, { id: 2, name: "Bob" }, { id: 3, name: "Carol" } ]; const user = users.find(u => u.id === 2); // → { id: 2, name: "Bob" } // No match → undefined const missing = users.find(u => u.id === 99); // → undefined // Find first number greater than 10 [3, 7, 15, 22].find(n => n > 10); // → 15 (stops here, doesn't check 22) // Guard against undefined with optional chaining const foundName = users.find(u => u.id === 99)?.name ?? "Not found"; // → "Not found"
💡 find vs filter: find returns ONE element (or undefined) and stops early. filter always scans the whole array and returns an array (possibly empty). Use find when you expect/want a single result — it's more efficient and semantically clearer.
Fi

.findIndex()

non-mutating → index or -1

Same idea as find, but returns the index of the first match instead of the element itself. Returns -1 if nothing matches (never undefined).

array.findIndex((element, index, array) => boolean)
const users = [{ id: 1 }, { id: 2 }, { id: 3 }]; const idx = users.findIndex(u => u.id === 2); // → 1 // No match → -1 (NOT undefined!) users.findIndex(u => u.id === 99); // → -1 // Common use: update an item immutably by index function updateUser(users, id, changes) { const idx = users.findIndex(u => u.id === id); if (idx === -1) return users; // not found, return unchanged const copy = [...users]; copy[idx] = { ...copy[idx], ...changes }; return copy; } // Remove item at found index (immutable) const idx2 = users.findIndex(u => u.id === 2); const withoutIt = [...users.slice(0, idx2), ...users.slice(idx2 + 1)];
⚠ findIndex returns -1, not undefined, when nothing is found — a common source of bugs if you check if (!idx) since -1 is truthy but index 0 is falsy! Always check idx === -1 explicitly.

.every()

non-mutating → boolean

Returns true only if ALL elements pass the test. Short-circuits and returns false as soon as one element fails.

array.every((element, index, array) => boolean)
const ages = [18, 21, 25, 30]; ages.every(age => age >= 18); // → true (all adults) const ages2 = [15, 21, 25]; ages2.every(age => age >= 18); // → false (15 fails, stops there) // Form validation — all fields filled? const fields = { name: "Alice", email: "a@b.com", age: 30 }; const isValid = Object.values(fields).every(v => v !== "" && v != null); // → true // ⚠️ every() on an EMPTY array → always true! ("vacuous truth") [].every(x => x > 100); // → true (no elements to violate the condition)

.some()

non-mutating → boolean

Returns true if AT LEAST ONE element passes the test. Short-circuits and returns true as soon as one match is found.

array.some((element, index, array) => boolean)
const nums = [1, 3, 5, 8]; nums.some(n => n % 2 === 0); // → true (8 is even) const odds = [1, 3, 5]; odds.some(n => n % 2 === 0); // → false (none are even) // Check if an item exists (like "includes" but with a condition) const cart = [{ id: 1 }, { id: 2 }]; const hasItem = cart.some(item => item.id === 2); // → true // ⚠️ some() on an EMPTY array → always false [].some(x => true); // → false (nothing to satisfy the condition)

.flat()

non-mutating → new flattened array

Flattens nested arrays into a single-level array, up to a specified depth (default: 1 level). ES2019 addition.

array.flat(depth = 1)
// Default depth = 1 [1, [2, 3], [4, 5]].flat(); // → [1, 2, 3, 4, 5] // Nested deeper — needs explicit depth [1, [2, [3, [4]]]].flat(); // → [1, 2, [3, [4]]] (only 1 level!) [1, [2, [3, [4]]]].flat(2); // → [1, 2, 3, [4]] (2 levels) [1, [2, [3, [4]]]].flat(Infinity); // → [1, 2, 3, 4] (fully flat, any depth) // flat() also removes empty slots (sparse arrays) [1, , 3].flat(); // → [1, 3] (hole removed) // Practical: flatten paginated / grouped API results const pages = [["a", "b"], ["c", "d"], ["e"]]; pages.flat(); // → ["a", "b", "c", "d", "e"]

non-mutating → new array

Equivalent to map() followed by flat(1) — but done in a single, more efficient pass. Perfect when your mapping function returns an array per element and you want a flat result.

[n * 10] : []); // → [20, 40] (odd numbers "filtered out" via empty array) // Extract nested children arrays from objects const categories = [ { name: "Fruits", items: ["apple", "banana"] }, { name: "Veggies", items: ["carrot"] } ]; categories.flatMap(c => c.items); // → ["apple", "banana", "carrot"]
💡 flatMap only flattens 1 level deep — it's equivalent to map().flat(1), not flat(Infinity). For deeper flattening you still need .flat(depth) separately after mapping.

Chaining these methods together

Because every method here returns a new array (except reduce, find, findIndex, every, some), you can chain them fluently to build data pipelines.

const orders = [ { id: 1, item: "Book", price: 15, qty: 2, shipped: true }, { id: 2, item: "Pen", price: 2, qty: 10, shipped: false }, { id: 3, item: "Laptop", price: 900, qty: 1, shipped: true } ]; // filter → map → reduce pipeline: total revenue from shipped orders const shippedRevenue = orders .filter(o => o.shipped) // keep shipped only .map(o => o.price * o.qty) // compute line totals .reduce((sum, total) => sum + total, 0); // sum them up // → (15*2) + (900*1) = 930 // find + map style access const laptopPrice = orders.find(o => o.item === "Laptop")?.price ?? 0; // → 900 // every / some for validation before processing const allInStock = orders.every(o => o.qty > 0); // → true const anyUnshipped = orders.some(o => !o.shipped); // → true
⚠ Performance note: chaining .filter().map() iterates the array twice. For huge arrays where performance matters, a single .reduce() pass can do both in one iteration. For typical interview/app code, readability of chaining usually wins.
!

Common Gotchas & Traps

  • ⚠️forEach vs map: forEach always returns undefined — it's for side effects only. Using its return value, or chaining after it, is a bug. Use map when you need a new array back.
  • ⚠️reduce without initial value on an empty array throws: [].reduce((a,b) => a+b) → TypeError. Always pass an initial value as the second argument.
  • ⚠️findIndex/indexOf return -1, not undefined/null — check with === -1 explicitly, since -1 is truthy but 0 (a valid index) is falsy.
  • ⚠️every() on empty array → true; some() on empty array → false — "vacuous truth" rule. This trips people up in validation logic on unfilled arrays.
  • ⚠️map without a return inside the callback silently returns an array of undefined: arr.map(x => { x * 2 }) — missing curly-brace return is a classic bug (use implicit return: x => x * 2).
  • ⚠️These methods skip empty/sparse slots — [1, , 3].map(x => x * 2) → [2, <empty>, 6], the hole is preserved, callback not invoked for it.
  • ⚠️flat() default depth is only 1, not full flatten. Use flat(Infinity) for arbitrarily nested arrays.
  • ⚠️Methods that DO mutate (contrast!): push, pop, shift, unshift, splice, sort, reverse, fill, copyWithin. Note sort() and reverse() mutate the ORIGINAL array even though people often expect otherwise — use [...arr].sort() for a safe copy.
  • ⚠️Array-like objects (arguments, NodeList, string) don't have these methods directly — convert first: Array.from(arrayLike) or [...arrayLike].
  • ⚠️Callback receives 3 arguments (element, index, array) — passing a function with extra expected params like arr.map(parseInt) is a famous bug because parseInt(val, index) uses the index as a radix!

Interview Q&A — click to reveal

Q1: What's the difference between map() and forEach()?
+
map() returns a new array built from the callback's return values — use it when you need the transformed data. forEach() always returns undefined and is meant purely for side effects (like logging or pushing to an external array). Chaining after forEach() or using its return value is a common mistake.
Q2: How would you reimplement filter() using reduce()?
+
const myFilter = (arr, predicate) => arr.reduce((acc, el) => { if (predicate(el)) acc.push(el); return acc; }, []);
This demonstrates that reduce is the most general iteration method — map, filter, and even find can all be expressed in terms of it.
Q3: What does array.every() return on an empty array? Why?
+
true — this is called "vacuous truth" in logic: if there are no elements to violate the condition, the condition is considered satisfied for all (zero) of them. Conversely, some() on an empty array returns false, since there's nothing to satisfy the condition.
Q4: What's the difference between find() and filter()?
+
find() returns the first matching element (or undefined) and stops iterating as soon as it finds a match — more efficient when you only need one result.

filter() always scans the entire array and returns an array of all matches (possibly empty). Use find for "get me the one item", use filter for "get me all matching items".
Q5: What's the difference between flat() and flatMap()?
+
flat(depth) only flattens an already-nested array — it takes no transformation function, just a depth (default 1).

flatMap(fn) is map(fn) immediately followed by flat(1) — it transforms each element AND flattens the result by exactly one level, done in a single efficient pass. Use flatMap when your mapping function itself produces arrays that you want merged into the parent array.
Q6: Why is arr.map(parseInt) a bug? What does it actually produce for ["1","2","3"]?
+
map calls the callback with 3 arguments: (element, index, array). parseInt also accepts a second argument — the radix (base). So map unintentionally passes the index as the radix.
["1","2","3"].map(parseInt); // parseInt("1", 0) → 1 (0 index, radix 0 → treated as base 10) // parseInt("2", 1) → NaN (radix 1 is invalid) // parseInt("3", 2) → NaN ("3" is not a valid base-2 digit) // → [1, NaN, NaN]
Fix: ["1","2","3"].map(n => parseInt(n, 10)) or .map(Number).
Q7: How do you remove duplicates from an array using these methods?
+
Simplest: [...new Set(arr)] (not one of these 9, but the standard trick).

Using filter (for arrays of primitives):
const unique = arr.filter((val, idx) => arr.indexOf(val) === idx); // keeps only the FIRST occurrence of each value
Using reduce (works for objects too, with a key function):
const uniqueBy = (arr, key) => arr.reduce((acc, item) => { if (!acc.some(x => x[key] === item[key])) acc.push(item); return acc; }, []);
Q8: Do these methods mutate the original array?
+
No — all 9 methods covered here (map, filter, reduce, find, findIndex, every, some, flat, flatMap) are non-mutating; they return new values and leave the original array untouched.

Contrast with mutating methods: push, pop, shift, unshift, splice, sort, reverse, fill. Notably sort() and reverse() surprise people because they mutate in place — use [...arr].sort() to avoid mutating the original.
Q9: How would you find the max value in an array of objects by a property, using reduce?
+
const products = [ { name: "A", price: 10 }, { name: "B", price: 45 }, { name: "C", price: 22 } ]; const mostExpensive = products.reduce((max, p) => p.price > max.price ? p : max ); // → { name: "B", price: 45 }
Note: no initial value needed here since the array is non-empty — the first element becomes the starting accumulator.
