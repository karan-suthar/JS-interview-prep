✓ Primitives are immutable — operations always produce a new value; the original is never changed in-place. Variables hold the actual value on the stack.
⚠ typeof null === "object" — a historic JS bug kept for backward compatibility. null is a primitive, not an object. Always use val === null to detect null.
// Primitive copy — always by value let a = 42; let b = a; // b gets a COPY of the value b = 100; console.log(a); // → 42 (unchanged!) console.log(b); // → 100 // String immutability let str = "hello"; str[0] = "H"; // silently fails (throws in strict mode) console.log(str); // → "hello" (still lowercase!) // null vs undefined let x; // → undefined (not assigned) let y = null; // → null (explicitly empty) console.log(typeof x); // → "undefined" console.log(typeof y); // → "object" ← famous gotcha! // Symbol — always unique const s1 = Symbol("id"); const s2 = Symbol("id"); console.log(s1 === s2); // → false (always unique!) // BigInt — precision beyond Number.MAX_SAFE_INTEGER const big = 9007199254740993n; console.log(big + 1n); // → 9007199254740994n ✓ console.log(9007199254740993 + 1); // → 9007199254740992 ✗ precision lost!

Reference types stored by reference

Objects, Arrays, Functions, Maps, Sets, Dates — anything that is an Object under the hood.

→ A variable does not hold the object itself — it holds a memory address (reference / pointer) to where the object lives on the heap.

// Objects — stored by reference let obj1 = { name: "Alice", age: 30 }; let obj2 = obj1; // obj2 points to the SAME object in memory obj2.age = 99; console.log(obj1.age); // → 99 ← obj1 also changed! console.log(obj2.age); // → 99 // Arrays — also reference types let arr1 = [1, 2, 3]; let arr2 = arr1; arr2.push(4); console.log(arr1); // → [1, 2, 3, 4] ← arr1 affected too! // Equality — compares references, NOT content let p = { x: 1 }; let q = { x: 1 }; console.log(p === q); // → false (different objects in memory) console.log(p === p); // → true (same reference)

Copying objects safely

⚠ Shallow copy — copies one level deep. Top-level primitives are independent, but nested objects/arrays are still shared references!
// 3 ways to shallow copy an object const original = { name: "Bob", scores: [10, 20] }; // 1. Spread operator (most common ✓) const copy1 = { ...original }; // 2. Object.assign() const copy2 = Object.assign({}, original); // 3. Array spread const arrCopy = [...original.scores]; // ⚠️ Shallow gotcha — nested array is still shared! copy1.name = "Charlie"; copy1.scores.push(30); console.log(original.name); // → "Bob" ✓ (primitive — independent copy) console.log(original.scores); // → [10, 20, 30] ← shared! nested ref not copied
✓ Deep copy — fully independent clone, all nested levels included. Use structuredClone() (modern, recommended) or carefully use the JSON trick.
const original = { name: "Alice", address: { city: "Delhi" } }; // 1. structuredClone() — modern, recommended (ES2022+) const deep1 = structuredClone(original); // 2. JSON trick — simple but has caveats const deep2 = JSON.parse(JSON.stringify(original)); // ⚠️ JSON trick LOSES: undefined, functions, Symbol, Date, RegExp, Map, Set deep1.address.city = "Mumbai"; console.log(original.address.city); // → "Delhi" ✓ (truly independent) console.log(deep1.address.city); // → "Mumbai" // structuredClone handles more types than JSON const withDate = { date: new Date(), map: new Map([["a", 1]]) }; const cloned = structuredClone(withDate); // ✓ Date stays Date, Map stays Map const broken = JSON.parse(JSON.stringify(withDate)); // ✗ Date → string, Map → {}
⚠ Object.freeze() prevents adding, removing, or editing properties. But it is shallow — nested objects remain mutable.
const config = Object.freeze({ env: "production", port: 3000 }); config.port = 8080; // silently fails (throws TypeError in strict mode) console.log(config.port); // → 3000 (unchanged) // ⚠️ Freeze is SHALLOW — nested objects are still mutable const obj = Object.freeze({ nested: { val: 1 } }); obj.nested.val = 99; // ← this DOES work! console.log(obj.nested.val); // → 99 (nested was not frozen) // Check if frozen console.log(Object.isFrozen(config)); // → true

Passing to functions — a key gotcha

primitive — pass by value
function double(n) { n = n * 2; // only local } let num = 5; double(num); console.log(num); // → 5 ✓
object — pass by reference
function rename(obj) { obj.name = "New"; // mutates! } let user = { name: "Old" }; rename(user); console.log(user.name); // → "New" !
✗ Reassigning the parameter variable inside a function does NOT affect the original — only mutating the object's properties does.
function tryReassign(obj) { obj = { name: "Brand New" }; // reassigns the LOCAL binding only } let person = { name: "Alice" }; tryReassign(person); console.log(person.name); // → "Alice" (original untouched!)

Interview Q&A — click to reveal

Q1: How many primitive types does JS have? Name them all.
+
7 primitives: string, number, boolean, null, undefined, symbol, bigint. Everything else (objects, arrays, functions, maps, sets, dates…) is a reference type.
Q2: What does typeof null return and why?
+
It returns "object" — a well-known bug from the original JS implementation preserved for backward compatibility. null is actually a primitive. To check for null reliably, use value === null.
Q3: Will {a:1} === {a:1} be true or false?
+
false — objects are compared by reference, not by content. These two object literals are stored at different memory addresses. To compare by content use JSON.stringify(a) === JSON.stringify(b) (simple cases) or a deep-equal utility for robust comparison.
Q4: What is the difference between null and undefined?
+
undefined: set automatically by the JS engine when a variable is declared but not yet assigned, or when a function returns nothing, or when an object property doesn't exist.

null: set intentionally by the developer to signal "no value here on purpose". Think of null as an empty box on purpose and undefined as a box that hasn't been set up yet.
Q5: How do you safely deep-clone an object?
+
Use structuredClone(obj) — modern, built-in, handles Date, Map, Set, ArrayBuffer, etc. correctly (ES2022+).

Avoid the JSON trick (JSON.parse(JSON.stringify(obj))) when the object contains undefined, functions, Symbols, Dates, Maps, or Sets — these are silently lost or corrupted.
Q6: Are arrays primitives or reference types? How do you check if something is an array?
+
Arrays are reference types (objects). typeof [] returns "object", not "array".

To check for arrays use Array.isArray(value) — this is the most reliable method. You can also use value instanceof Array or Object.prototype.toString.call(value) === "[object Array]".
Q7: What happens when you pass an object to a function and reassign the parameter?
+
Reassigning the parameter inside the function does not affect the original variable — it only changes where the local binding points. However, mutating a property of the object (obj.name = "x") DOES affect the original because both the outer variable and the parameter reference the same object in memory.
